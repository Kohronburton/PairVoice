# PairVoice Troubleshooting & Revenue Protection
P0 = security/duplicate money/cross-user secret exposure. P1 = material revenue/capacity block. P2 = isolated workflow issue. P3 = cosmetic.

Credentials: never reuse an active/problem bundle; revoke/problem it and issue a distinct replacement. Duplicate assignment is P0/P1.
Pairing: never overwrite an existing pair; partner replacement deactivates old membership and preserves history.
QA: Complete never means Payable. Redos create new attempts.
Money: never edit/delete ledger history. Retry payouts by idempotency key, never as a second independent payment.
Revenue: if credential capacity or approval rate drops, throttle acquisition before buying unusable volume.
Incident evidence: campaign/version, pair, participants, redacted bundle, expected/current state, request IDs, audit/activity events, revenue exposure, recovery, root cause and regression test.
