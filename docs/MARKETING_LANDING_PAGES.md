# Implementation Requirements

Do not create two unrelated hard-coded products. Build a reusable campaign landing page with configuration fields such as:

- `campaignId`
- `countryCode`
- `locale`
- `language`
- `currency`
- `publicPayoutAmount`
- `payoutUnit` (`PAIR`)
- `approvalRequired`
- `participantCount`
- `eligibilityRulesVersion`
- `primaryCTA`
- `consentVersion`
- `membershipOfferEnabled`
- `referralOfferEnabled`

Recommended routes:

- `/us` or `/campaigns/us-english`
- `/es` or `/campaigns/es-spain`

The region layer should select the appropriate campaign presentation while allowing the user to manually change country/language. Analytics must retain campaign ID and locale through eligibility, signup, partner invitation, submission, approval and payment.

10. Project submitted

12. Payment due
13. Paid
14. PairVoice+ offer viewed
15. PairVoice+ subscribed
16. Referral invite sent
17. Referred contributor approved

# Trust Rules

- Never state or imply that acceptance, approval or earnings are guaranteed.
- Never describe compensation as per person when it is per pair.
- Never make PairVoice+ a condition of receiving earned approved compensation.
- Never fabricate testimonials, payment totals, scarcity or countdowns.
- Show applicable consent and recording-use information before participation.
- Preserve the workflow distinction: COMPLETED != ACCEPTED != PAYMENT_DUE != PAID.
